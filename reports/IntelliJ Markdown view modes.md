# Bring IntelliJ's three Markdown modes to VEGA

IntelliJ opens every `.md` file in one tab that has three layouts: **Editor only**, **Editor and Preview** (a split inside the tab), and **Preview only**. Three toggle buttons at the top right switch between them. The preview is an embedded Chromium page that updates as you type and follows the editor's scroll in one direction only. VEGA (through Zed's code) already has a good native preview with click-to-source, Mermaid and clickable checkboxes, but the preview is a separate tab, there is no visible mode switcher, no "split by default" option, and no scroll sync. The cheapest way to close the gap is a new fork crate that adds a three-button switcher to the pane toolbar and drives preview functions that are already public. This needs about two one-line changes in upstream files. A default-layout setting comes next, then scroll sync, which is the only step that needs a real (but small and additive) change inside an upstream crate. I recommend not building a true single-tab composite editor now: it is the most faithful copy of IntelliJ, but it is also the most expensive option and the one most likely to break on upstream merges. Nothing in this report was built or run; the VEGA findings come from reading the code, and some IntelliJ details come from JetBrains' unreleased `master` branch, which I mark where it matters.

## IntelliJ puts editor and preview inside one tab with a three-button switcher

The Markdown editor in JetBrains IDEs is a platform component called "text editor with preview". It has exactly three states, named in the code as **"Editor only"**, **"Editor and Preview"** and **"Preview only"** ([TextEditorWithPreview.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)). The help pages use the short names "Editor" and "Preview" and say: "By default, the Markdown editor shows a preview pane for rendered HTML code next to the Markdown source" ([JetBrains help](https://www.jetbrains.com/help/idea/markdown.html)). So the default for a new user is the split.

The switcher is three toggle buttons in a fixed order: Editor only, Editor and Preview, Preview only. The button for the current layout is shown as selected. In the current "new UI" the buttons sit at the right end of the editor tab row (since 2023.1). In the classic UI, or when editor tabs are hidden, they appear as a floating toolbar over the editor, **25 px from the top and 20 px from the right**, which shows on mouse movement and hides **1400 ms** after the mouse stops or when you press a key ([TextEditorWithPreview.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)). The same actions are in Find Action as "View as Editor", "View as Editor with Preview" and "View as Preview". They have no default keyboard shortcut ([ActionsBundle.properties](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-resources-en/src/messages/ActionsBundle.properties)).

In the split, the editor is always the first pane (left or top) and the preview is the second (right or bottom). Side by side is the default. The direction is a global setting called "Preview layout" under Settings | Languages & Frameworks | Markdown. Clicking the already-selected "Editor and Preview" button flips the direction for that one editor ([ChangePreviewLayoutAction.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/ChangePreviewLayoutAction.kt)), but the global setting wins again when the file is reopened ([MarkdownEditorWithPreview.java](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)). The divider is a thin draggable line, and its position is stored once for the whole IDE, not per file.

What IntelliJ remembers is worth copying exactly. The **view mode is stored per file** as part of the editor state, and the **last mode you used is stored globally** and applied to files you open for the first time. If nothing is stored, the split is used ([TextEditorWithPreview.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)). The preview is created only when it becomes visible and destroyed when hidden, so "Editor only" costs nothing ([MarkdownPreviewFileEditor.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownPreviewFileEditor.kt)). Switching to "Preview only" moves keyboard focus into the preview.

One change is coming that the owner should know about. The 2026.3 branch adds a fourth, experimental button, "Live Preview", which is off by default. On the unreleased `master` branch it is renamed "Editable Preview (Experimental)", it is on by default, and a new setting "Render preview in: JCEF / Editor" defaults to "Editor", which hides the split and preview-only buttons ([MarkdownEditorWithPreview.java](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java), [MarkdownSettingsState.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/settings/MarkdownSettingsState.kt)). It is not known which release will ship this. My reading of the code is that JetBrains is moving toward rendering inside the editor, without a browser. JetBrains has not said this publicly.

## The preview is a locked-down Chromium page, and scroll sync goes one way only

The preview is an embedded Chromium browser (JCEF). The IDE converts Markdown to HTML itself, then patches the page's DOM on each change after a **20 ms** debounce, so the page never reloads ([MarkdownUpdateHandler.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownUpdateHandler.kt), [IncrementalDOMBuilder.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/preview/impl/IncrementalDOMBuilder.kt)). A strict content security policy allows only the IDE's own scripts, so scripts written in a Markdown file do not run ([PreviewStaticServer.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/PreviewStaticServer.kt)). Colours come from the IDE theme, and the user can add or replace CSS. The renderer supports GitHub-flavoured Markdown (tables, strikethrough, task lists, autolinks) plus math, `==highlight==`, definition lists, front matter, GitHub alerts and footnotes ([MarkdownDefaultFlavour.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/lang/parser/MarkdownDefaultFlavour.kt)). Code blocks are coloured by the IDE's own highlighters and get a copy button. Mermaid and PlantUML are not on by default: the help says diagram rendering "is disabled by default and requires additional steps", meaning a separate Mermaid plugin and a PlantUML download ([JetBrains help](https://www.jetbrains.com/help/idea/markdown.html)).

Scroll sync is weaker than most people expect. **Scrolling the editor moves the preview. Scrolling the preview does not move the editor, and clicking in the preview does not jump to the source.** The page does send its scroll position back to the IDE, but no code listens for it ([ScrollSync.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/preview/ScrollSync.js), [MarkdownJCEFHtmlPanel.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/preview/MarkdownJCEFHtmlPanel.kt)). The mapping works because every HTML element carries its source range. In 2026.2 the IDE takes the editor's top visible line and scrolls the matching element into view. On `master` it computes a fractional position inside the element and eases toward it, which is smoother ([MarkdownPreviewFileEditor.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownPreviewFileEditor.kt)). Moving the caret alone does not scroll the preview. Requests for the missing directions have been open for years: sync from preview ([IJPL-93491](https://youtrack.jetbrains.com/issue/IJPL-93491)) and click-to-source, open since 2019 ([IJPL-91120](https://youtrack.jetbrains.com/issue/IJPL-91120)).

The preview itself is read-only. It has a find bar, font-size zoom, and a two-item right-click menu ("Adjust Font Size…" and "Find…"). Task-list checkboxes cannot be clicked ([IJPL-93542](https://youtrack.jetbrains.com/issue/IJPL-93542)), and a report that Ctrl+C does not copy from the preview has been open since 2020 with 25 votes ([IJPL-97844](https://youtrack.jetbrains.com/issue/IJPL-97844)). Export to HTML and PDF (and Word through Pandoc) reuses the rendered page, so it only works while the preview is visible ([JetBrains help](https://www.jetbrains.com/help/idea/markdown.html)). The browser dependency is also the main source of complaints: the most-voted open issues are about the preview not working with GPU acceleration (**70 votes**, [IJPL-59383](https://youtrack.jetbrains.com/issue/IJPL-59383)) and GPU-process restarts (**67 votes**, [IJPL-59371](https://youtrack.jetbrains.com/issue/IJPL-59371)).

## IntelliJ's source editor adds lists, tables, links and images on top of plain text

Selecting text shows a floating toolbar with a header-style menu, Bold, Italic, Strikethrough, Code, Create Link and a list-type menu. Each inline style is a toggle with a shortcut: Bold `⌘B`, Italic `⌘I`, Strikethrough `⌘⇧S`, Code `⌘⇧C`, Create Link `⌘⇧U`, Insert Image `⌘U` (Ctrl instead of ⌘ on Windows and Linux) ([JetBrains help](https://www.jetbrains.com/help/idea/markdown.html), [intellij.markdown.xml](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/resources/intellij.markdown.xml)). Pasting a URL over selected text makes `[text](url)` automatically ([MarkdownLinkPastePreProcessor.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/editor/MarkdownLinkPastePreProcessor.kt)). An "Insert…" popup offers Link, Table, Image and Table Of Contents.

Lists and tables get the most help. In lists, Enter adds the next item, Enter on an empty item ends or outdents the list, Backspace removes the marker, and Tab / Shift+Tab change nesting together with child items ([MarkdownListEnterHandlerDelegate.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/editor/lists/MarkdownListEnterHandlerDelegate.kt)). In tables, Tab / Shift+Tab move between cells, Shift+Enter adds a row, and bars around the table offer insert, move, align and remove for rows and columns ([JetBrains help](https://www.jetbrains.com/help/idea/markdown.html)). A newer option aligns table columns visually "without modifying the table's source text" ([settings reference](https://www.jetbrains.com/help/idea/markdown-reference.html)). The defaults tell a useful story: on `master`, "Reformat table when typing" and "Renumber list when typing" are both **off** ([MarkdownCodeInsightSettings.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/settings/MarkdownCodeInsightSettings.kt)). JetBrains turns off the features that rewrite the user's text without being asked. VEGA should follow the same rule.

Headings drive the Structure view, breadcrumbs, folding, and a generated table of contents between `<!-- TOC -->` markers with a warning when it is out of date ([GenerateTableOfContentsAction.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/editor/toc/GenerateTableOfContentsAction.kt)). Links to files and `#heading` anchors have completion, Ctrl+Click navigation, rename, and warnings for broken targets. Images can be dragged in or pasted; a pasted screenshot is saved as a PNG next to the Markdown file with no dialog and no naming choice ([MarkdownImagePasteProvider.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/images/src/main/kotlin/org/intellij/plugins/markdown/images/editor/paste/MarkdownImagePasteProvider.kt)). Code fences with a language tag get that language's highlighting and completion, and shell blocks get a run icon. Errors inside code fences are a known annoyance, and "Show errors in code fences" is now off by default.

## VEGA already beats IntelliJ on click-to-source but has no modes, no split default, no scroll sync

VS Code uses a different model. The preview is a separate tab (`⇧⌘V`) or a tab in the group beside (`⌘K V`), and one shared preview follows the active file unless you lock it ([VS Code docs](https://code.visualstudio.com/docs/languages/markdown)). Scroll sync works in both directions and both settings are on by default ([package.json](https://raw.githubusercontent.com/microsoft/vscode/main/extensions/markdown-language-features/package.json)). Mermaid became built in with VS Code 1.121 (May 2026) ([release notes](https://code.visualstudio.com/updates/v1_121)), and an experimental rich "Markdown Editor" that edits the rendered text arrived in 1.131 (July 2026) ([release notes](https://code.visualstudio.com/updates/v1_131)). Obsidian has three presentations (Source mode, Live Preview, Reading view) and renders in place instead of splitting ([Obsidian Help](https://obsidian.md/help/edit-and-read)). The in-place approach has a real cost. When Cursor replaced the split preview with a combined editor, a user wrote: "Please make this an option because the UX is a total regression in editing and previewing markdown" ([Cursor forum](https://forum.cursor.com/t/please-do-not-convert-to-your-new-markdown-editor-keep-the-open-in-preview/148571)). A reviewer of VS Code's new editor called it "oddly jittery" ([Thurrott](https://www.thurrott.com/dev/340776/visual-studio-code-now-includes-a-full-markdown-editor)). The lesson is to keep the split and offer in-place rendering only as an option.

VEGA's Markdown code is still upstream Zed's: the fork differs from upstream in these crates by one line. The preview is one view, `MarkdownPreviewView`, which is its own tab bound to a source editor (`crates/markdown_preview/src/markdown_preview_view.rs:71-89`). `cmd-shift-v` opens it in the same pane and `cmd-k v` opens it in the pane to the right (`assets/keymaps/default-macos.json:643-647`). An eye button in the quick action bar does the same, but it disappears when the preview tab is active, because that bar only shows for editor items (`crates/zed/src/zed/quick_action_bar.rs:773-822`). Sync follows the cursor, not the scroll position: moving the editor cursor highlights and reveals the matching block in the preview, and a single click in the preview moves the editor cursor there (`markdown_preview_view.rs:578-590`, `:1175-1186`). Scrolling with the wheel on either side does not move the other side; the preview has no handler for the editor's scroll event (`markdown_preview_view.rs:561-594`). Rendering is native GPUI with the pulldown-cmark parser, a whitelist of HTML tags, built-in Mermaid, clickable checkboxes that edit the source, find, and text selection with copy. Math is deliberately turned off in the parser (`crates/markdown/src/parser.rs:1044-1047`).

| Topic | IntelliJ | VS Code | VEGA / Zed today |
|---|---|---|---|
| Where the preview lives | Same tab as the editor | Separate tab or side group | Separate tab, same or side pane |
| Mode switcher | Three buttons, always visible | Title buttons and "Reopen With" | Eye button, hidden on the preview tab |
| Default for a new file | Split | Editor | Editor (preview-only is opt-in) |
| Split direction | Right or below (global setting) | Editor-group layout | Right only |
| Scroll sync | Editor to preview only | Both directions | None (cursor sync only) |
| Click preview to reach source | No | Double-click (setting) | Single click |
| Checkbox click in preview | No | Only in experimental editor | Yes, edits the source |
| Mermaid | Separate plugin | Built in | Built in, native |
| Math | Yes (MathJax) | Yes (KaTeX) | No |
| Custom CSS | Yes | Yes | No (fonts and width only) |
| Table and format commands | Many | Only in experimental editor | Not found in the notes |

Upstream Zed will probably not build the missing parts soon. Staff closed the live-preview request as "not something that is on our nearterm roadmap" ([issue #15066](https://github.com/zed-industries/zed/issues/15066)), and a community live-preview PR was closed in August 2026 because no Zed owner had confirmed the direction ([PR #62593](https://github.com/zed-industries/zed/pull/62593)). Users do ask for exactly what IntelliJ has. On the issue about opening Markdown in preview by default (about 118 thumbs-up), one user wrote "I'd like it to open in split preview so I can both edit the Markdown", and another said there is no visible way to switch modes ([issue #10966](https://github.com/zed-industries/zed/issues/10966)). Math is different: two community PRs are open with no staff decision ([PR #54668](https://github.com/zed-industries/zed/pull/54668)), so the fork should wait for upstream there instead of writing its own.

## Build the switcher first, then the default layout, then scroll sync

There are two ways to get three modes. The first keeps the editor and the preview as separate tabs and adds a switcher that arranges them in panes. The second creates a new composite tab type that contains both, as IntelliJ does. I recommend the first. The composite needs to be opened in place of the normal editor for every `.md` file, must forward the whole tab interface (save, search, navigation, breadcrumbs, restore), and breaks every place in the code that asks "is this tab an `Editor`?". The only existing example of such a composite, `SplittableEditor`, combines two editors, not an editor and another kind of view (`crates/editor/src/split.rs:534-554`). The pane approach reuses functions that are already public and matches the direction upstream is taking, so merges stay cheap. Its cost is honest: "Editor and Preview" stays two tabs in two panes, so closing one does not close the other, and the mode is worked out from what is open instead of being stored.

| Order | What to build | Where the code goes | Upstream files touched |
|---|---|---|---|
| 1 | Three-button switcher (Editor / Split / Preview) and three actions | New fork crate with its own `ToolbarItemView`, calling `open_preview_in_pane`, `open_preview_to_the_side_of_pane` and `CloseAndReturnToEditor` | One `toolbar.add_item` line in `crates/zed/src/zed.rs`, one `init` line in `crates/zed/src/main.rs`, workspace `Cargo.toml` |
| 2 | `default_layout` setting: `editor`, `split` or `preview` | Fork crate: own settings struct and its own `ItemAdded` hook | Additive lines in `crates/settings_content/src/settings_content.rs` and `assets/settings/default.json`; optional line in `crates/settings_ui/src/page_data.rs` |
| 3 | Editor scroll moves the preview (IntelliJ level) | Fork crate listens to `EditorEvent::ScrollPositionChanged` and asks the preview to reveal the top visible line | One small `pub` accessor on `MarkdownPreviewView` |
| 4 | Exact two-way scroll sync (VS Code level) | Fork crate, with a guard so the two sides do not trigger each other | Additive public mapping functions in `crates/markdown/src/markdown.rs` |
| 5 | Editing commands: format toggles, URL paste, table Tab and Shift+Enter, image paste | Fork crate; seams not researched yet | Unknown |
| 6 | Renderer gaps: math, more HTML tags | Wait for upstream | None |

**Step 1** gives the owner the visible result he asked about. The toolbar item shows when the pane's active tab is a Markdown editor or a Markdown preview, so the buttons stay visible in all three modes. Each pane has its own toolbar, so the same switcher appears above both halves of the split. "Editor only" closes this file's preview tabs and focuses the editor. "Split" calls the existing side-pane function. "Preview only" opens the preview in the same pane and removes the editor tab, the same way the upstream auto-preview hook already does (`markdown_preview_view.rs:186-195`), and must never close an editor with unsaved changes. Existing small toolbars such as `SoloDiffStyleToolbar` are the pattern to copy (`crates/git_ui/src/solo_diff_view.rs:558-650`). Keep the `cmd-shift-v` and `cmd-k v` shortcuts, and leave the upstream eye button alone: removing it means editing an upstream file for no gain.

**Step 2** makes split the default possible, which is IntelliJ's default and what Zed users ask for. The setting must define what happens when the upstream boolean `open_markdown_files_in_preview` is also set; the simplest rule is that the new key wins when present. The hook should copy the upstream guards: do nothing while the workspace is restoring, and keep its own list of files where the user chose "Editor only", so the preview does not reopen against the user's choice.

**Steps 3 and 4** are scroll sync. Step 3 reaches IntelliJ's level with one small accessor, but the existing preview scroll is "reveal with a margin", so the two sides can sit most of a screen apart (`crates/markdown/src/markdown.rs:2588-2622`). Step 4 needs the source-to-pixel mapping in `crates/markdown`, which is private today (`markdown.rs:5084-5094`). That file is large and changes often upstream, so the change should be a few added `pub` functions and nothing else. Another public Zed fork merged a combined split view with two-way sync in October 2026, which shows it is possible, but its design was not readable from the PR page ([superzent PR #71](https://github.com/currybab/superzent/pull/71)).

Three IntelliJ behaviours have no cheap seam yet, and the owner should decide whether they matter: a split with the preview **below** (the existing function always opens to the right), **per-file memory** of the mode (no store exists for it), and one-tab lifetime. Step 5 is independent of the preview and can run in parallel, starting with what JetBrains keeps on by default: format toggles, URL paste over a selection, and table cell navigation. Zed already continues lists on Enter ([Zed docs](https://zed.dev/docs/languages/markdown)). The notes did not look at where these commands would attach in the editor code, so that needs a short investigation first.

## Conclusion

IntelliJ's Markdown view looks richer than it is. Its real strengths are the always-visible three-way switcher, split as the default, and remembered modes. Its preview is one-way, read-only and tied to a browser that often fails, and JetBrains itself appears to be moving away from it. VEGA starts from the opposite position: a solid native preview with exact source mapping, missing only the layout layer around it. That layer is cheap, and most of it fits in one new crate.

The useful target is therefore not a copy of IntelliJ but IntelliJ's switcher and defaults on top of Zed's preview, with VS Code's two-way scroll sync as the stretch goal. Two points remain open and code reading cannot settle them: whether a split made of two tabs feels acceptable in daily use compared with one tab, and whether the same switcher above both panes reads well. A prototype of step 1 answers both in the shortest time, and nothing in steps 1 to 3 blocks moving to a composite tab later if the answer is no.
