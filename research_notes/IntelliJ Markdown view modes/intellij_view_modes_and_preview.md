# IntelliJ / JetBrains Markdown view modes and preview (bundled Markdown plugin)

Scope note. Findings are from (a) the official help pages as served on 2026-11-20 (page footer date "06 November 2026", image paths under `/2026.3/`), (b) the open-source plugin in `JetBrains/intellij-community`, read at `master` commit `ebff02cd06c4` (2026-11-19) and compared against release branches `193`…`263` (branch number = version: `262` = 2026.2, `263` = 2026.3), and (c) YouTrack's public API. `master` is unreleased development code and differs from 2026.2/2026.3 in important ways (called out below). The same plugin ships in IntelliJ IDEA, PhpStorm, WebStorm, PyCharm, CLion, etc.; I only read the IDEA help pages, the search results show identical wording on the CLion/WebStorm pages.

Source shorthand used in links: `TEWP` = `platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt`; `MEWP` = `plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java`.

## 1. The three view modes, their names, the switcher, and how the UI changed

### Takeaway
The Markdown editor is a platform "text editor with preview" with exactly three layouts: `Editor only`, `Editor and Preview`, `Preview only` (toolbar tooltips/labels; the help calls the buttons "Editor", "Editor and Preview", "Preview"). The three toggle buttons sit at the top-right: as a floating, auto-hiding toolbar over the editor (since 2021.3), or, in the new UI with editor tabs visible, as actions at the right end of the editor tab strip (since 2023.1). In unreleased `master` a fourth, in-editor mode "Editable Preview (Experimental)" exists and is the default rendering mode.

### Cited Findings
- Platform class doc: "Two-panel editor with three states: Editor, Preview and Editor with Preview." The enum is `Layout { SHOW_EDITOR("Editor only"), SHOW_PREVIEW("Preview only"), SHOW_EDITOR_AND_PREVIEW("Editor and Preview") }`; the string in quotes is both the persisted id and the English display name (`tab.title.editor.only`, `tab.title.preview.only`, `tab.title.editor.and.preview`). — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)
- Find Action / Search Everywhere names of the same actions: "View as Editor", "View as Editor with Preview", "View as Preview" (action ids `TextEditorWithPreview.Layout.EditorOnly` / `.EditorAndPreview` / `.PreviewOnly`). No default keyboard shortcut is declared for them in the plugin XML I read. — [ActionsBundle.properties](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-resources-en/src/messages/ActionsBundle.properties)
- Button order in the group is fixed: Editor only, Editor and Preview, Preview only (`createViewActionGroup`). They are `ToggleAction`s (radio-like: the one matching the current layout is shown selected). — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt), [ChangePreviewLayoutAction.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/ChangePreviewLayoutAction.kt)
- Icons: `AllIcons.General.LayoutEditorOnly`, `AllIcons.General.LayoutPreviewOnly`; for the split button `AllIcons.General.LayoutEditorPreview` (side by side) or `AllIcons.General.EditorPreviewVertical` (stacked) in the new UI, and `AllIcons.Actions.PreviewDetails` / `PreviewDetailsVertically` in the classic UI. The split button's icon changes to reflect the current orientation. The help page references the same icons as `app.expui.general.editorOnly.svg`, `previewOnly.svg`, `editorPreview.svg`, `editorPreviewVertical.svg`. — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt); [help](https://www.jetbrains.com/help/idea/markdown.html)
- Official wording: "By default, the Markdown editor shows a preview pane for rendered HTML code next to the Markdown source. You can click Editor or Preview in the top right corner of the Markdown editor to show only the editor or the preview pane." — [Markdown help](https://www.jetbrains.com/help/idea/markdown.html)
- Floating toolbar mechanics: used when registry key `ide.text.editor.with.preview.show.floating.toolbar` is true (default `true`, description "Show a floating toolbar with layouts instead of a permanent toolbar") and the editor has no left toolbar. It is drawn on the popup layer of a layered pane over the whole split component, positioned `toolbarTopPadding = 25` px from the top and `toolbarRightPadding = 20` px from the right edge. It is shown on mouse movement inside the editor component, hidden 1400 ms after the last movement unless the pointer is over the toolbar, hidden when the pointer leaves, and hidden on any key press in the text editor. Otherwise (registry off) a permanent toolbar row is placed at `BorderLayout.NORTH` above the split. — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt); [registry.properties](https://github.com/JetBrains/intellij-community/blob/master/platform/util/resources/misc/registry.properties)
- New-UI placement: `isShowActionsInTabs = isNewUI() && editorTabPlacement != TABS_NONE`. When true the three actions are returned from `getTabActions()` (rendered at the right end of the editor tab row) and the floating/permanent toolbar group returns no children. So in the default new UI the switcher is in the tab strip; the floating toolbar only appears in the classic UI or when editor tabs are set to "None". — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)
- Version history, read from release branches:
  - 2019.3 (`193`): only a JavaFX preview provider exists; 2020.1–2020.2 (`201`, `202`): both JavaFX and JCEF providers; 2020.3 (`203`) onward: JCEF only. — [193 JavaFxHtmlPanelProvider](https://github.com/JetBrains/intellij-community/blob/193/plugins/markdown/src/org/intellij/plugins/markdown/ui/preview/javafx/JavaFxHtmlPanelProvider.java), [202 JCEFHtmlPanelProvider](https://github.com/JetBrains/intellij-community/blob/202/plugins/markdown/src/org/intellij/plugins/markdown/ui/preview/jcef/JCEFHtmlPanelProvider.java), [203 tree](https://github.com/JetBrains/intellij-community/tree/203/plugins/markdown/src/org/intellij/plugins/markdown/ui/preview)

  - 2023.1 (`231`): `getTabActions` / `isShowActionsInTabs` first present (buttons move to the tab strip in the new UI); absent in `221`. — [231](https://github.com/JetBrains/intellij-community/blob/231/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.java), [221](https://github.com/JetBrains/intellij-community/blob/221/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.java)

- Switching to `Preview only` explicitly moves keyboard focus into the preview component (comment: "Editor tab will lose focus after switching to JCEF preview"). In `Editor only` and split modes the text editor is the preferred focus target. — [MEWP](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)
- The hidden text editor still accepts actions in preview-only mode (`ALLOW_ACTION_PERFORM_WHEN_HIDDEN`, "FIXME: better solution IDEA-354102"). — [MEWP](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)
- The preview component is created lazily and destroyed when hidden: a visibility listener attaches the HTML panel on `componentShown` and disposes it on `componentHidden`, so `Editor only` costs no browser instance. — [MarkdownPreviewFileEditor.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownPreviewFileEditor.kt)

### Inferences
- An equivalent implementation needs one composite editor holding a text editor and a preview, a 3-state enum, three mutually exclusive toggle buttons at the tab-strip right edge (or a floating overlay 25 px/20 px from the top-right that fades after about 1.4 s of no mouse movement), and lazy creation/teardown of the preview.
- The "Editor" / "Preview" labels in the help are short forms of the tooltips "Editor only" / "Preview only".

### Gaps
- I could not confirm from a primary source the exact look of the pre-2021.3 permanent toolbar (which buttons, e.g. whether an "Auto-Scroll Preview" toggle sat there); branch `212` has toolbar/auto-scroll code in the Markdown editor class but I did not read it. What's New pages for 2020.3–2022.2 returned no Markdown text to my fetches.
- Whether 2026.3 is already generally available on 2026-11-20 is unconfirmed: the unversioned help page uses `/2026.3/` image paths, while search-result titles still say "IntelliJ IDEA 2026.2 Help".
- Which release the `master` behaviour (default "Render preview in: Editor") will ship in is unknown.

## 2. How the split works

### Takeaway
Editor is always the first pane (left or top), preview the second (right or bottom). Default is side by side. Orientation is a global setting ("Preview layout"); clicking the already-selected "Editor and Preview" button flips orientation for that editor only. The divider is a draggable 1 px splitter whose proportion is stored under one global key. The view mode is remembered both globally (last used, for newly opened files) and per file (editor state).

### Cited Findings
- `splitter.firstComponent = editor`, `splitter.secondComponent = preview`; splitter is a `OnePixelSplitter` with divider width 1 (new UI) or 2 (classic), coloured with editor colour key `PREVIEW_BORDER_COLOR`. — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)
- Help: "By default, the editor and the preview are split vertically (side by side), which is convenient for wide monitors. You can also split it horizontally, so that the preview is displayed in the lower part of the editor". Procedure: click the "Open Editor Preview" button, then click it again "to split the editor and the preview horizontally". "To configure the default layout of the preview, you can use the Preview layout list in Languages & Frameworks | Markdown." — [Markdown help](https://www.jetbrains.com/help/idea/markdown.html)
- The second click is implemented in the toggle action: deselecting the `SHOW_EDITOR_AND_PREVIEW` action calls `editor.setVerticalSplit(!editor.isVerticalSplit())`. Separate actions also exist: group "Split Layout" with "Vertical Layout" and "Horizontal Layout". — [ChangePreviewLayoutAction.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/ChangePreviewLayoutAction.kt), [ChangeEditorSplitActions.kt](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/ChangeEditorSplitActions.kt), [ActionsBundle.properties](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-resources-en/src/messages/ActionsBundle.properties)
- Naming trap: the Markdown setting `isVerticalSplit` (default `true`, label "Split vertically") means side by side; the platform's `isVerticalSplit` means stacked, so the Markdown editor passes `!settings.isVerticalSplit()` everywhere. — [MEWP](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java), [MarkdownSettingsState.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/settings/MarkdownSettingsState.kt)
- Orientation persistence: the per-file editor state stores `isVerticalSplit`, but the Markdown editor overrides it after restore: "'Preview layout' is a global default, so it must win over the per-file orientation restored from a full editor state. See IJPL-253568." Changing the setting re-orients all open Markdown editors live. The same override is present on `262`. — [MEWP master](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java), [MEWP 262](https://github.com/JetBrains/intellij-community/blob/262/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)
- View-mode persistence, global: `setLayout` writes the layout id to application-level `PropertiesComponent` under key `"${name}Layout"`; the Markdown editor's name is "Markdown Split Editor", so the key is `Markdown Split EditorLayout`. A new editor with no explicit layout reads this "last used" value, falling back to `SHOW_EDITOR_AND_PREVIEW`. — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt), [MarkdownBundle.properties](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/resources/messages/MarkdownBundle.properties)
- View-mode persistence, per file: `getState` returns `MyFileEditorState(splitLayout, firstState, secondState, isVerticalSplit)` and `setState` restores `splitLayout` (layout is excluded only for the `UNDO` state level). — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)
- `master` only: an empty file never opens in "Preview only" even if that was last used ("An empty file must not open in 'Preview only', because the user then sees no text to edit"); it opens in the split instead. — [MEWP](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)
- Divider proportion: `splitterProportionKey` defaults to `"TextEditorWithPreview.SplitterProportionKey"`; doc comment: "From all the text editors that don't override this method, only a single proportion is stored." The Markdown plugin does not override it (no match in `plugins/markdown`). — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)
- A file can be forced to open in preview-only via `TextEditorWithPreview.openPreviewForFile(project, file)` (sets a per-file default-layout key). — [TEWP](https://github.com/JetBrains/intellij-community/blob/master/platform/platform-impl/src/com/intellij/openapi/fileEditor/TextEditorWithPreview.kt)

### Inferences
- Net behaviour: view mode = "per file when the file has saved editor state, otherwise the globally last-used mode"; orientation = global; divider position = one global ratio shared by every editor-with-preview in the IDE (Markdown and other file types). Initial ratio is presumably the splitter default of 50/50 (not read in source).
- The per-editor orientation flip via the second click is transient for Markdown (lost on reopen because the global setting wins).

### Gaps
- A "Default layout:" combo (Editor only / Preview only / Editor and Preview) exists on the settings page in branches `221` through `262` and is gone in `263`; `master` marks the backing property `@Deprecated("The default layout setting is no longer available.")`. I could not find where `262` applied it to new editors (neither the editor class nor the split provider references it), so its real effect in 2022.1–2026.2 is unverified.

## 3. Settings under Settings | Languages & Frameworks | Markdown, with defaults

### Takeaway
All settings are application-level (stored in `markdown.xml`) except the custom CSS file path, which is per project. Defaults: preview layout "Split vertically" (side by side), sync scroll on, preview font size = editor font size, inject languages on, show errors in code fences off (it was on through 2026.2), custom CSS off, PlantUML not installed.

## 4. Scroll synchronisation

### Takeaway
Sync is one-way in practice: scrolling the editor drives the preview; scrolling the preview does not move the editor, and clicking in the preview does not jump to the source. Mapping uses source-offset ranges stamped on every rendered element. `master` adds a continuous, fractional "follow" algorithm; 2026.2 scrolls the element for the editor's top visible line into view.

### Cited Findings
- Trigger: a `VisibleAreaListener` on the text editor; ignored when sync is off or when the vertical position did not change. — [MEWP](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)
- 2026.2 algorithm: take the logical line at the top of the editor viewport (`xyToLogicalPosition(Point(0, verticalScrollOffset))`); if it changed since last time call `scrollToLine(editor, line)`, which resolves to the visual-line end offset and runs `window.scrollController.scrollTo(offset, smooth=true)`. — [MEWP 262](https://github.com/JetBrains/intellij-community/blob/262/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java), [MarkdownHtmlPanel.java](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownHtmlPanel.java)
- Element mapping: the HTML generator writes a source-range attribute on each element, value `"from..to"`; the attribute name is passed to the page in `<meta name="markdown-position-attribute-name">`. `scrollTo(offset)` walks the DOM for the deepest element whose range contains the offset (searching forward or backward to the nearest mapped element if none), skips if the offset is still inside the current target element, then `scrollIntoView({behavior: "smooth"})`. — [ScrollSync.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/preview/ScrollSync.js), [MarkdownJCEFHtmlPanel.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/preview/MarkdownJCEFHtmlPanel.kt)
- `master` "follow" algorithm (`followEditor` → `scrollToSourceOffset`): the IDE computes a fractional source offset for the top of the viewport (top visual line start + fraction of the line scrolled × line length) and the page converts it to a pixel Y by descending the mapped block elements and linearly interpolating between the enclosing element's top and bottom (special case for inline children), clamps to the scrollable range, and eases toward it each animation frame with time constant 40 ms; the loop aborts if the user scrolled the preview themselves (scrollY differs by more than 1 px from what the loop applied). — [MarkdownPreviewFileEditor.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownPreviewFileEditor.kt), [ScrollSync.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/preview/ScrollSync.js)
- Caret: on every re-render the caret offset and line are passed as `initialScrollOffset`, but the page only uses it on the first render of a panel (`firstUpdate -> scrollController.scrollTo(initialScrollOffset, true)`), i.e. when the preview is (re)opened it starts at the caret position. Caret movement alone does not scroll the preview. — [MarkdownPreviewFileEditor.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownPreviewFileEditor.kt), [MarkdownJCEFHtmlPanel.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/preview/MarkdownJCEFHtmlPanel.kt)
- Preview-to-editor: the page does post a throttled (20 ms) `setScroll` message with the source offset of the top element on scroll, and the panel forwards it to `ScrollListener`s, but no code in the plugin registers a listener (`addScrollListener` has no callers outside its declarations). — [ScrollSync.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/preview/ScrollSync.js), [MarkdownJCEFHtmlPanel.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/preview/MarkdownJCEFHtmlPanel.kt)
- Click handling in the preview page is limited to `<a>` elements; there is no click-to-source handler. — [processLinks.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/extensions/processLinks/processLinks.js)
- Boundary helper: when the editor is already at its top/bottom and the wheel keeps turning, the wheel delta is forwarded to the preview (`scrollBy`) so the preview can reach its own ends (registry `markdown.experimental.boundary.precise.scroll.enable`, default true). — [PreciseVerticalScrollHelper.java](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/PreciseVerticalScrollHelper.java)
- An action "Sync Scroll" ("Sync the preview panel scroll with the editor", icon `AllIcons.Actions.SynchronizeScrolling`) toggles sync for the current editor only and is enabled only in the split layout; it is registered in group `Markdown.Toolbar.Right`. — [intellij.markdown.xml](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/resources/intellij.markdown.xml), [AutoScrollAction.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/actions/scrolling/AutoScrollAction.kt)
- Structure view / header navigation scrolls the preview too (`navigateToHeader` → `scrollToLine`) in `master`. — [MEWP](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownEditorWithPreview.java)
- Open requests for the missing directions: "Markdown. Sync scroll from preview." ([IJPL-93491](https://youtrack.jetbrains.com/issue/IJPL-93491), open, 2023), "Scroll markdown when clicking the preview" ([IJPL-91120](https://youtrack.jetbrains.com/issue/IJPL-91120), open, 2019), "Markdown preview out of sync when soft-wrap enabled" ([IJPL-245655](https://youtrack.jetbrains.com/issue/IJPL-245655), open, 2026).
- Help text describes it as "the scrollbars in the editor and in the preview pane are synchronized, meaning that the location in the preview pane corresponds to the location in the source." — [Markdown help](https://www.jetbrains.com/help/idea/markdown.html)

### Inferences
- The `master` design (fractional offset → interpolated Y → exponential easing, abort on user scroll) is the more robust model to copy; the older "scroll top-line element into view" model is what causes the jumpiness users report with tall elements (images, tables, code blocks).
- The current `master` toolbar does not appear to place the "Sync Scroll" toggle anywhere visible (the Markdown editor no longer supplies a right-toolbar group); it is reachable via Find Action. Not verified in a running IDE.

### Gaps
- No double-click-to-source or selection sync was found; I did not run the IDE to confirm absence empirically.

## 5. Preview rendering technology

### Takeaway
The preview is an embedded Chromium (JCEF) page served from the IDE's built-in localhost web server under a strict Content-Security-Policy; Markdown is converted to HTML in the IDE (JetBrains `markdown` library, GFM flavour plus extensions) and applied to the page as an incremental-DOM patch on every document change. Theme colours come from a generated stylesheet rebuilt from the IDE theme. Scripts in the document do not run.

### Cited Findings

- JCEF unavailable: settings page shows "There are no available preview providers." and hides preview options; on `263`/`master` the editor is forced to `Editor only` and the switcher offers only Editor + Live/Editable Preview. - IDE↔page messaging: a JSON `{type, data}` pipe (`window.__IntelliJTools.messagePipe.post/subscribe`), injected only for the preview page URL. Events seen: `documentReady`, `setScroll`, `openLink`, `copy-button/copy`. — [BrowserPipe.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/preview/BrowserPipe.js)
- Theme: stylesheet order is `baseStyles/default.css` (or the user's CSS file, which replaces it), then a generated colours stylesheet, then extension styles, then `inlineStyles/inline.css` (the "CSS rules" text, priority `AFTER_ALL`). - Raw HTML passes through the generator and Jsoup into the DOM. - Images: `<img src>` that is not browser-owned (anything without a scheme, or `file:`) is rewritten to an IDE-served URL and the original kept in `data-original-src`; resolution goes through the VFS relative to the document; files outside the project root are refused when the project is not trusted; watched image files trigger a re-render after a 200 ms debounce. `http(s):`, `data:` and `//host` sources are left for Chromium to load. Base CSS sets `img { max-width: 100% }`. — [IncrementalDOMBuilder.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/preview/impl/IncrementalDOMBuilder.kt), [MarkdownPreviewPathResolver.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownPreviewPathResolver.kt), [MarkdownImageResourceProvider.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/MarkdownImageResourceProvider.kt), [default.css](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/resources/org/intellij/plugins/markdown/extensions/common/baseStyles/default.css)

Anything else is posted to the IDE: `source://path:offset` opens that file at the offset; non-`file` URIs open in the system browser (`BrowserUtil.browse`) with no prompt for protocols on the project's safe list (http/https by default per the code comment) and a yes/no confirmation with a "do not ask again for this protocol" option otherwise; links resolving to local files open in the IDE: Markdown files in an editor tab, `file.md#anchor` navigates to the matching header (a list popup of "header text (file:line)" entries if several headers match, warning balloon "Cannot find header to navigate to" if none), non-Markdown files open in the editor with GitHub-style `#L10` line fragments honoured, directories are selected. Registry `markdown.open.link.in.external.browser=false` disables link following. — [processLinks.js](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/resources/com/intellij/markdown/jcef/extensions/processLinks/processLinks.js), [ProcessLinksExtension.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/jcef/src/com/intellij/markdown/jcef/extensions/ProcessLinksExtension.kt), [MarkdownLinkOpenerImpl.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/frontend/src/com/intellij/markdown/frontend/preview/accessor/impl/MarkdownLinkOpenerImpl.kt), [MarkdownSourceLinkNavigator.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/ui/preview/accessor/MarkdownSourceLinkNavigator.kt)
- Code fences: highlighted in the IDE, not in the browser. The fence's info string is mapped to an IDE language; the IDE lexer/highlighter produces coloured ranges (cached) emitted as `<span>` elements with colours from the editor colour scheme; unknown languages are escaped plain text. A copy button is injected per fence (`.code-fence-highlighter-copy-button`); it copies via the IDE clipboard and shows a status-bar message. — [MarkdownCodeFencePreviewHighlighter.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/extensions/common/highlighter/MarkdownCodeFencePreviewHighlighter.kt), [FenceHighlighting.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/extensions/common/highlighter/FenceHighlighting.kt), [CodeFenceCopyButtonBrowserExtension.kt](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/core/src/org/intellij/plugins/markdown/extensions/common/highlighter/CodeFenceCopyButtonBrowserExtension.kt)
- Runnable commands: inline code and shell fences that look like runnable commands get a run icon in the preview (setting "Detect commands that can be run right from Markdown files"). — [intellij.markdown.execution.xml](https://github.com/JetBrains/intellij-community/blob/master/plugins/markdown/execution/resources/intellij.markdown.execution.xml), [settings reference](https://www.jetbrains.com/help/idea/markdown-reference.html)
- JetBrains' own description (2022): the preview "is conveniently located next to the editor and provides fast and smooth incremental updates as you type. The scroll bar in the preview is synchronized with the editor"; "There have been a lot of complaints in the past about the speed and accuracy of the preview." — [JetBrains blog, Aug 2022](https://blog.jetbrains.com/idea/2022/08/markdown-support-improvements/)

### Inferences
- `<script>` elements and inline event handlers in a Markdown file do not execute: the CSP allows scripts only from the explicit list of IDE resource URLs and has no `'unsafe-inline'`; iframes, audio/video, objects and XHR/fetch are also blocked (`child-src`, `media-src`, `object-src`, `connect-src` all `'none'`). Inline `style` attributes and `<style>` blocks do work (`style-src … 'unsafe-inline'`), which is why the click-guard exists. I did not see an explicit tag sanitizer, so the CSP is the enforcement point.
- Remote images load by default (`img-src *` plus the registry default allowing external requests).
- Task-list checkboxes are display-only in the JCEF preview (there is CSS for `input[type="checkbox"]` but no click handler; "Toggle checkmark in markdown preview" [IJPL-93542](https://youtrack.jetbrains.com/issue/IJPL-93542) is still open).

### Gaps
- When exactly incremental-DOM patching replaced full-page reloads is not pinned to a version (the builder file is at a different path in 2020–2021 branches; I did not locate it).
- The safe-protocol default list in `DocumentLinksSafeState` was not read; "http/https" is from a code comment.
- The source-position attribute's literal name comes from the external `markdown` library constant `HtmlGenerator.SRC_ATTRIBUTE_NAME`; I did not read its value.

## 6. Diagram support (Mermaid, PlantUML)

### Takeaway
Neither renders out of the box. Mermaid rendering is delivered by a separate JetBrains "Mermaid" plugin installed from the Marketplace; PlantUML is a built-in extension that needs a one-click download of `plantuml.jar` and renders to a PNG in the IDE process.

## 7. Preview-only mode: selection, find, zoom, context menu, separate window/browser, export

### Takeaway
The preview is a read-only Chromium view: text can be selected with the mouse, there is an in-preview find bar, font-size zoom, and a two-item right-click menu. There is no built-in "open preview in browser" or detach-preview action; sharing is via Export to HTML/PDF/DOCX, which requires the preview to be visible.

### Inferences
- A preview in its own window is only achievable generically: the Markdown tab (in Preview-only mode) can be dragged out or split like any editor tab; the preview pane itself cannot be detached from its editor. Not verified in a running IDE.
- Mouse text selection works because it is a normal Chromium page; the open copy issue suggests the keyboard shortcut is swallowed by the IDE in at least some configurations.

### Gaps
- Not verified by running the IDE: whether Ctrl/Cmd+C works in current builds, whether Ctrl/Cmd+wheel zooms (open issue "Mouse Zoom in / Out not working in Markdown preview window", [IJPL-197644](https://youtrack.jetbrains.com/issue/IJPL-197644)), and whether "Select All" works in the preview.

## 8. Known complaints and long-standing limitations

### Takeaway
The recurring themes are: JCEF fragility (blank preview, GPU problems, unsupported runtimes), sync that is one-way and imprecise, awkward copy/zoom in the preview, images referenced from raw HTML, and the switcher's placement. Vote counts are modest (tens, not hundreds) but several issues have been open for 4–7 years.

### Inferences
- The in-editor "Live/Editable Preview (Experimental)" mode on `263`/`master`, and `master` defaulting "Render preview in" to `Editor`, read as JetBrains' answer to the JCEF-dependence and "make preview editable" complaints: it renders headings, lists, checkboxes ("Toggle Markdown Task"), images, rules and code fences inline in the text editor (renderer classes under `editor/livepreview`) with no browser. This is my reading of the code, not a JetBrains statement.
- Several `master` code comments reference recent security fixes (IJPL-247801, IJPL-247809) aimed at CSS-based click hijacking and referrer leaks, so preview hardening was active work in 2026.
